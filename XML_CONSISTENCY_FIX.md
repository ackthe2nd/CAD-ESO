# XML Generation Consistency Fixes

This document describes the changes made to fix inconsistencies between the XML data saved in log files and the XML data uploaded via SFTP or logged to Google Sheets.

## Issues Fixed

1. **Inconsistent GPS Coordinates**: The `SceneGpsLocationLat` and `SceneGpsLocationLong` fields were sometimes missing in the generated XML.
2. **Missing Timestamp Fields**: Some timestamp fields like `IncidentOrOnset`, `DispatchNotified`, and `UnitNotifiedByDispatch` were sometimes empty.
3. **Call Nature Information**: The `CallNature` field was sometimes missing data.

## Implementation Details

The fixes involved several key changes to the code:

### 1. Enhancing GPS Coordinate Extraction

Added a more robust mechanism to extract GPS coordinates from multiple possible sources in the API response:

1. Direct `Latitude` and `Longitude` fields in the call data
2. `Geolocation` string from the call data
3. Coordinates in the `extraGetData` object
4. **New Source**: Location data from the unit activity entries, which often contain accurate GPS data even when other sources don't

```javascript
// Added code to extract GPS coordinates from unit activity data
if ((!latitude || !longitude) && extraGetData.Data && extraGetData.Data.Activity) {
  const activityWithLocation = extraGetData.Data.Activity.find(a => 
    a.Type === 'Unit' && a.Location && typeof a.Location === 'string'
  );
  
  if (activityWithLocation && activityWithLocation.Location) {
    const locationParts = activityWithLocation.Location.split(',');
    if (locationParts.length === 2) {
      latitude = locationParts[0].trim();
      longitude = locationParts[1].trim();
    }
  }
}
```

### 2. Complete Call Data Consolidation

Enhanced the call data consolidation to ensure all fields are included in the final XML:

```javascript
const completeCallData = {
  ...callData,
  ...callDataForXml,
  
  // Ensure we have complete information
  CallId: callExtraData.CallId || callData.CallId,
  LoggedOn: callExtraData.LoggedOn || callExtraData.LoggedOnUtc || callData.Timestamp,
  Name: callExtraData.Name || callData.Name,
  
  // GPS coordinates
  Latitude: callExtraData.Latitude || 
    (typeof callExtraData.Geolocation === 'string' ? 
     callExtraData.Geolocation.split(',')[0] : ''),
  Longitude: callExtraData.Longitude || 
    (typeof callExtraData.Geolocation === 'string' ? 
     callExtraData.Geolocation.split(',')[1] : ''),
  
  // Ensure we have call nature details
  Nature: callDataForXml.Nature || callExtraData.Name || callData.Name || ''
};
```

### 3. Improved Variable Handling

Fixed issues with undefined variables that were causing errors during XML generation:

```javascript
// Before: Accessing undefined 'nature' variable
Nature: nature || callExtraData.Nature || ''

// After: Using properly defined variables
Nature: callDataForXml.Nature || callExtraData.Name || callData.Name || ''
```

### 4. Enhanced Error Reporting

Added more detailed error logging to help diagnose issues with the XML generation process:

```javascript
logger.error(`Error processing call ${callData.CallId}: ${error.message}`);
console.error(`Error processing call ${callData.CallId}: ${error.message}`);
console.error(error.stack); // Log the stack trace for debugging
```

## Testing and Verification

The fixes were tested by:

1. Restarting the workflows and monitoring the log files
2. Examining the generated XML files to ensure all fields are properly populated
3. Checking Google Sheets logging to confirm data consistency

## Benefits

These changes ensure that:

1. All XML files generated by the system are consistent, whether saved to logs, uploaded via SFTP, or logged to Google Sheets
2. GPS coordinates are reliably included when available from any data source
3. All important timestamp fields are properly populated
4. Fewer errors occur during the XML generation process
